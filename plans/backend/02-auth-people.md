# 02 · Вход, люди, доступ

**Цель.** В портал можно войти, роли и доступ к группам работают и читаются из базы на каждом
запросе; администратор заводит группы, сотрудников и пользователей; отзыв согласия уничтожает
связь «номер → человек».

**Зависит от:** 01

## Задачи

### auth
- [x] Вход: логин + пароль (argon2id) → cookie `arena_session` (httpOnly, Secure, SameSite=Strict,
      8 часов без действий); `login` и `login_failed` в журнал; частота 5/мин на пару «адрес + логин».
      Сессия входа — подписанная cookie (D-19), ключ выводится из секрета HMAC (D-21), флаг
      `Secure` — из `ARENA_COOKIE_SECURE` (D-22).
- [x] Middleware `RequireUser`: достаёт пользователя **из базы** на каждом запросе, проверяет
      `is_active`.
- [x] Middleware ролей по матрице `arena-portal-hr.md` 5 — роли берутся из `x-roles` контракта
      (`httpx.LoadOperationAccess`), отказ пишется под действием операции (D-24).
- [x] **Закрыть `GET/PATCH /api/portal/settings`**, открытые в 01 без входа (D-16): чтение —
      М, Н, А; правка — только администратор.
- [x] Контракт `auth.GroupAccess`: `Check(ctx, userID, groupID)` и `SQLFilter` для подмешивания
      `s.group_id IN (…)`; отказ → 403 `forbidden_group` + журнал `denied` (I-3, I-4).
- [x] Токены тренажёра (HMAC): участник, гость демо, репетиция — выпуск и проверка; сами адреса
      появятся в 07, 10, 11.
- [x] Пользователи: список, создание, правка (роль, имя, пароль, отключение), доступ к группам
      (`access_granted` / `access_revoked`).
- [x] `me`: роль и группы с доступом.

### people
- [x] Группы: список с признаком доступа, создание, правка (название, подразделение, профиль, архив).
- [x] Сотрудники: создание с новым `subject` (номер `N-XXXXXX`, ключ данных, обёрнутый мастер-ключом),
      список по группе, карточка, правка и перевод между группами.
- [x] Контракт `people`: `DataKey(ctx, subjectID)` → ключ или «уничтожен»; имя для экранов с доступом.
- [x] Отзыв согласия: одна транзакция из пяти шагов (архитектура 9.3). Отмену назначений и кодов
      делает `assignments` — до этапа 07 через интерфейс потребителя, который ничего не делает.
- [x] Отзыв только согласия на внешнюю нейросеть → `external_ai_withdrawn_at`, `external_ai_withdrawn`.

### audit (адреса)
- [x] Журнал с фильтрами (период, пользователь, группа, номер участника), выгрузка CSV
      (`audit_exported` в журнал).

## Адреса

`auth`: `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `GET|POST /users`,
`PATCH /users/{userId}`, `PUT /users/{userId}/group-access`
`people`: `GET|POST /groups`, `PATCH /groups/{groupId}`, `GET|POST /people`,
`GET|PATCH /people/{subjectId}`, `POST /people/{subjectId}/consent-withdrawal`
`audit`: `GET /audit-log`, `POST /audit-log/export`
(всё под `/api/portal`)

## Ловушки

- Роль в cookie не кладём. Снятый доступ действует на следующем же запросе.
- Результаты администратора — тоже только по доступу к группе.
- `DELETE` у `arena_app` есть только на `people` и `user_group_access`; остальное — `UPDATE`.
- После отзыва согласия все пути чтения текстов должны работать без ключа.
