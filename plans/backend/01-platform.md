# 01 · Платформа, журнал, настройки

**Цель.** Любой модуль можно собрать из готовых кирпичей: транзакция с журналом, ошибка
по-русски в `problem+json`, проверка тела по схеме, шифрование, частота запросов.
Сгенерированный strict server подключён через явный адаптер (D-17). Работают
`GET/PATCH /api/portal/settings` — пока без входа (D-16), роль администратора навешивается в 02.

**Зависит от:** 00

## Задачи

### platform
- [x] `config`: обязательные переменные (`ARENA_DATABASE_URL`, `ARENA_MASTER_KEY`,
      `ARENA_CODE_HMAC_SECRET`) — при отсутствии падение с понятным текстом. Оба секрета —
      base64, ровно 32 байта после декодирования, иначе отказ старта с именем переменной (D-15);
      `.env.example` и `project/README.md` — с командой `openssl rand -base64 32`. Необязательные
      `ARENA_STT_*`, `ARENA_GEN_*`, `ARENA_DEMO` (по умолчанию вкл.), `DEMO_MODEL_KEYS`;
      печать режима при старте (архитектура 11.2); время старта процесса.
- [x] `pg`: пул, `WithTx(ctx, fn)`, `Savepoint`, перевод кодов PostgreSQL (unique, fk, check,
      insufficient_privilege) в доменные ошибки с именем ограничения.
- [x] `httpx`: ответ `problem+json` (`type`, `title` по-русски, `errors[]` с JSON Pointer);
      таблица «доменная ошибка → код и `type`» по `arena-portal-hr.md` 8.1.
- [x] `httpx`: ограничение размера (1 МБ JSON, 5 МБ запись репетиции, 25 МБ mp3) → 413.
- [x] `httpx`: **фильтр `emotion`** — обход разобранного JSON, точное имя ключа, до любого
      логирования (I-1). Исключение — два multipart-адреса.
- [x] `httpx`: проверка тела по JSON Schema из нетронутого `api/arena-api.yaml` библиотекой
      `santhosh-tekuri/jsonschema/v6` (D-04, D-14); схема по операции; `$ref` на несуществующий
      `arena-scenario.schema.json` → «любой объект»; закрытые схемы → 400 `invalid_body` с путями.
      Тело разбирается один раз (вместе с фильтром `emotion`) и возвращается в `r.Body` для
      сгенерированного обработчика.
- [x] `httpx`: пагинация `limit/offset` (до 200), фильтры повтором параметра, ответ `{items, page}`.
- [x] `httpx`: изменяющие запросы принимают только `application/json` (кроме multipart-исключений).
- [x] `log`: структурированный `slog`; тела запросов не логируются вообще; помощник, который
      не даёт положить в лог поля с именами и текстами (I-5).
- [x] `crypto`: AES-256-GCM (nonce перед шифром), обёртка/распаковка ключа участника мастер-ключом,
      HMAC-SHA256, argon2id (хеш и сверка), шифр ключей провайдеров мастер-ключом.
- [x] `ratelimit`: скользящее окно в памяти; четыре предела из `arena-portal-hr.md` 8.1; 429
      с `Retry-After`.

### сборка API (D-17)
- [x] `cmd/portal/api.go`: структура `api` с полями-обработчиками модулей и по методу на каждую
      из 82 операций `gen.StrictServerInterface`; секции по модулям в порядке архитектуры 13.2;
      `var _ gen.StrictServerInterface = (*api)(nil)`.
- [x] Общая ошибка «ещё не реализовано» → 501 `problem+json` с русским `title`; ею отвечают все
      операции, чьи модули ещё не сделаны. Секция `settings` — первая настоящая.
- [x] `NewStrictHandlerWithOptions`: `RequestErrorHandlerFunc` и `ResponseErrorHandlerFunc`
      отвечают `problem+json` по-русски, а не текстом генератора (I-8).
- [x] Порядок middleware на роутере: лимит размера → фильтр `emotion` и проверка по схеме →
      лог запроса → сгенерированный обработчик. Место для четырёх ручных адресов авторства
      (D-05) — отдельная группа `chi`, в этапе 01 пустая.

### модули
- [x] `audit`: `contract.go` с `Write(ctx, tx, Entry)` — вызывается внутри транзакции
      потребителя; `store` только `INSERT`/`SELECT`. Адреса чтения и выгрузки — в 02 после входа.
- [x] `settings`: чтение и правка одной строки `portal_settings`, демо-флаг из окружения,

## Ловушки

- Фильтр `emotion` должен стоять **до** любого middleware логирования запроса.
- Подстрока не считается: `emotion_labels_to_opponent` — законное имя.
- Журнал пишется той же `tx`, что и действие; отдельного соединения у `audit` нет.
- `title` — фраза для экрана, не английский текст ошибки Go.
- Адаптер вызывает метод модуля **по имени**: не заменять его встраиванием — тогда неверная
  сигнатура молча превратится в 501 (D-17).
- `PATCH /settings` открыт до 02 (D-16) — не забыть закрыть ролью администратора в 02.
- Линтер границ модулей (D-11) в исходном виде запрещал импорт `internal/modules/*` из
  **любого** файла — это блокировало и законную зависимость `settings` → `audit`. Уточнено
  в D-18: запрет — только для `store.go` и `transport.go`; `contract.go`, `module.go`,
  `service.go` импортируют контракты других модулей свободно.
